# File memory

This module is inert: it has no production callers or registered tools. Storage is user-level, with global memories in `<home>/.praana/memory` and project memories in `<home>/.praana/projects/<key>/memory`. The key is the real git root (or real cwd outside git), a readable basename plus a six-character SHA-256 suffix. When realpath fails (including inaccessible or non-directory components), the normalized absolute path is the fallback identity. Worktrees are not unified.

`createFileMemoryStore({ home, cwd, now?, fs?, findRoot?, incognito? })` requires an explicit home. Its methods are:

- `write({ scope, name, type, description, body })`: strict validation, secret refusal, advisory duplicate check, atomic upsert. Names are safe lowercase slugs; descriptions are at most 300 Unicode code points on one line; bodies are at most 2048 UTF-8 bytes. Feedback/project bodies require Why/How lines. Unknown write keys are rejected. Policy-only validation lives in `validateMemoryPolicy`.
- `read({ name, scope? })`: parsed memory; project takes precedence without a scope.
- `remove({ name, scope? })`: hard delete, including malformed or oversized regular files. Two removable matches require an explicit scope. An unscoped delete is refused when any scope scan failed, because that scope might hold a same-named memory; the error asks for an explicit scope. A stray symlink/directory in one scope never blocks deletion of a regular file in the other; only non-removable matches produce a clear error.
- `list({ scope? } = {})`: frontmatter entries, whole-day ages and stale flags (>90 days), plus skipped count. Invalid files are skipped; disappearing files are treated as absent.
- `buildMemoryIndex({ scope? } = {})`: derives `{ text, truncated, shown, total }` from directory listings and bounded frontmatter reads, never `MEMORY.md`. It throws on unsafe directories or filesystem failures. The pure renderer is also exported from `index.ts` for already-collected `IndexEntry` values.
- `recall({ name?, query? })`: exactly one argument. Name lookup returns the parsed memory. Query lookup returns `{ ok: true, matches }`, at most five `{ name, scope, description, snippet }` records. Both corpus and query are NFC-normalized, then split into runs of Unicode letters, marks and numbers (marks alone are not empty). Unsegmented CJK text becomes one long token; substring matching is out of scope. Unique case-insensitive tokens score 9/3/1 for name/description/body; ties use updated descending, name, then scope. Empty/stop-word-only queries are rejected by the separate `validateQueryPolicy`.
- `refreshIndexFile(scope)`: atomically regenerates that scope's `MEMORY.md` from that scope's entries only. Returns a typed success/error result; writes and removals await it but deliberately ignore refresh failures after committing the authoritative change. Links in this copy are relative to its own directory (`(<name>.md)`) so they resolve where the file is written.

`createFileMemoryTools(store)` from `tools.ts` returns `remember`, `recall` and `forget_memory` definitions without registering them. Each execution safe-parses a strict Zod schema (including unknown-key rejection) and catches validation/store exceptions into `{ ok: false, error }`. Store refusals, including duplicate suggestions, are returned unchanged. The tool descriptions state the storage/search limits.

`MEMORY_POLICY`, exported by `index.ts` and `store.ts`, describes which durable observations to save and which transient or derivable information not to save.

The index selects the newest prefix across both scopes (updated descending, scope, name), then groups global before project. Caps are 200 lines and 25,600 UTF-8 bytes, including separators and the exact overflow line, excluding the fixed untrusted-data preface. Overflow capacity is reserved before selection. Ages render as `0d`, `3d`, etc. The prompt index links are scope-qualified (`(<scope>/<name>.md)`) because it spans both scopes; the copy written into a scope directory uses links relative to that directory (`(<name>.md)`). Links use only validated `<slug>.md` basenames. Backslashes and Markdown brackets are escaped together so hand-edited links cannot become live links. Descriptions are truncated to 300 code points before Markdown escaping; controls/newlines become spaces. Recall snippets use a window of at most 300 code points centred on the first matching body token, falling back to a matching description token, or the body's start for name-only matches.

## Safety and concurrency

The user may symlink `.praana` or its ancestors; the real `.praana` is the containment root. A dangling `.praana` symlink produces an explicit error rather than being recreated. Descendant directory symlinks are refused, as are symlinked memory files. Directories are created with mode 0700 and files with 0600. Reads are bounded to 64 KiB per memory and 8 KiB normalized frontmatter. Writes reject secret-shaped text rather than persisting even a redacted version, identifying only the affected fields. **Hand-edited files are not secret-scanned**; do not put secrets in memory files. The index and recall are untrusted observations, never instructions.

Atomic same-directory exclusive temp creation, file fsync and rename provide last-writer-wins replacement. Directory fsync is best effort. There are no locks: duplicate checks and `created` are advisory under races; list/read/index are not snapshots. `MEMORY.md` may briefly be stale and is never authoritative or read back. Failed writers remove only their own temp file; orphan temp files from crashed writers are ignored and are not collected. The abrupt-termination test kills a real child with SIGKILL after its temp write acknowledgement, before rename, checking both existing and absent targets as well as all derived readers. Concurrency tests release separate processes from a stdin barrier, check every result/exit, and assert exact unique survivors and complete shared-name versions. A write/delete race and an in-process supplement cover the same atomicity model. Filesystem-seam recording checks containment for every path-taking call in parent and child tests; static import scans keep the module production-inert.
